# Chart Battle

「バズを買え。ピークで売れ。」Xトレンド仮想トレードゲームのプロトタイプ。Phase 2の売買機能をベースに、**ライトなデザインのホーム・プレイ・結果画面**を実装しています。

モック投稿件数から仮の指数を作り、24時間分のチャートを時間に沿って描画します。10,000コインで購入・売却し、終了時の総資産をスコアとして確認できます。Next.js App Router / React / TypeScript / SVG + D3-shapeで構成しています。X API・Firebase・認証はまだ実装していません。

## 起動

Node.js 22.20.0以上を使用します。APIキーや環境変数は不要です。

```sh
npm ci
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000) を開きます。終了はターミナルで Ctrl+C。

```sh
npm test
npm run typecheck
npm run build
npm start
```

`npm start`はビルド後のアプリを起動します。

## 画面と操作

| URL       | 画面   | 主な操作                                           |
| --------- | ------ | -------------------------------------------------- |
| `/`       | ホーム | 市場選択、プレイ開始、あそび方                     |
| `/play`   | プレイ | トレード開始、購入・売却、一時停止、やり直し       |
| `/result` | 結果   | スコア確認、チャートの振り返り、再挑戦、ホーム復帰 |

- ホームで市場を選び「プレイする」または「この市場でプレイ」を押します。プレイ画面の「トレード開始」で時計が進みます。
- 再生中に「1口買う」「1口売る」を押すと1口ずつ取引できます。保有上限は10口です。
- 24時間分のチャートを1分で再生します。一時停止中は残り時間が進みません。
- プレイ中に「あそび方」を開くと自動で一時停止します。
- やり直しと、プレイ中のホーム復帰には確認を出します。キャンセルした場合は直前の状態で続けられます。
- ブラウザーの戻る操作でホームへ移動した場合も自動で一時停止します。「途中のプレイに戻る」で保有分を引き継いで戻れます。途中のプレイを新しいプレイで置き換える場合は確認を出します。
- 終了時に結果画面へ自動で移動します。「もう一度プレイ」で資金・保有・履歴を初期化してプレイ画面へ戻ります。
- プレイ中の売買欄に保有口数を10目盛りのゲージで表示し、残りコインを並べます。スマートフォンでは売買欄を画面下部に固定します。スコアと損益は終了後の結果画面で確認できます。
- タブが非表示になると自動で一時停止します。戻ったら手動で再開してください。
- 同じタブ内の画面移動では状態を維持します。永続化はしていないため、再読み込みや別タブでは初期状態です。結果がない状態の`/result`にはホームへの導線を表示します。

## 売買の仮ルール

正式な経済システムを決める前の、動作検証用のルールです。

- 初期資金10,000コイン。1口単位の現物取引で、手数料・借入・空売りはありません。
- 1指数ポイントを1口あたり1コインとして扱い、小数第2位に丸めた価格を画面表示と約定に共用します。
- 保有できるのは最大10口です。上限到達時や残高不足時は購入できず、保有が0口のときは売却できません。
- 注文クリック時に再生時計を精算し、その時刻のチャート価格で約定します。直前の描画フレームの古い価格は使いません。
- 一時停止中・開始前・終了後は取引できません。終了時刻ちょうどの注文も拒否します。
- 総資産 = 残りコイン + 保有数量 × 現在価格。損益 = 総資産 − 10,000コイン。
- 平均取得価格で原価を管理し、売却時は原価を保有数量の比率で配分します。
- 金額は0.01コイン単位の整数で計算します。一部売却の原価配分で生じた端数は、最後の売却時に精算します。
- 終了時は残りコインと最終価格での保有評価額を合算してスコアを確定します。保有分を自動売却した履歴は作りません。
- チャートのBは購入、Sは売却です。
- リセットすると資金・保有・取引履歴が初期状態に戻ります。シナリオ選択は別々の検証プレイとして扱います。

## 検証用の仮設定

**以下はゲーム仕様の確定ではありません。** 実データでの価格式・平滑化・再生倍率の検証後に見直します。

| 項目         | 初期実装                                                    |
| ------------ | ----------------------------------------------------------- |
| 投稿データ   | 24時間、5分間隔、3種類の固定モック                          |
| 指数         | 平滑化した投稿件数を初期値100に換算                         |
| 再生時間     | 60秒。`src/lib/replay/clock.ts`の`REPLAY_DURATION_MS`で設定 |
| 補間         | D3 `curveMonotoneX`。区間を滑らかにつなぐ                   |
| データ平滑化 | 各時点の前後20分を、近い時点ほど重くして平均                |
| 表示範囲     | 初期指数付近から開始し、再生済みの曲線に応じて拡張          |

開始区間で割る方法はモック比較用です。低い開始投稿数やゼロ投稿を含む実データにそのまま適用する仕様ではありません。

## 曲線と将来の売買の整合性

D3が生成した三次ベジェ曲線を座標として保持します。再生時刻で曲線を分割し、その**同じ曲線上の終点**を表示価格と約定価格に使います。チャートは連続した元の曲線を描き、コイン価格は小数第2位に丸めます。B/Sマーカーは注文時刻の曲線上に表示します。

これは過去データのリプレイです。補間用の曲線はシナリオ全体から事前生成しますが、画面には再生済みの曲線だけを渡します。軸の範囲にも全期間の高値・安値は使用しません。シナリオ選択の小さな波形はパターン説明用の固定イラストです。将来のリアルタイム価格処理では、未到着データを補間に利用できないため、別途検証が必要です。

再生時計は`requestAnimationFrame`の時刻差で進みます。停止・再開で再生位置が飛ばないように、一時停止中の時間を除外しています。実際の描画速度は端末によって異なります。

## チャート実装の選定

| 候補               | 判断                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| Recharts           | Reactとの親和性が高い。ゲームの再生時間と曲線評価の制御は別途必要      |
| Chart.js           | Canvasベースの有力候補。独自マーカーや描画制御は追加実装が必要         |
| Lightweight Charts | 金融チャートと追加更新に適する。将来の高度な取引画面では再検討可能     |
| **SVG + D3-shape** | **採用**。少量の時系列に対して、曲線・途中描画・現在位置を共有しやすい |

公式資料：[Recharts](https://recharts.github.io/en-US/api/Line/)、[Chart.js](https://www.chartjs.org/docs/latest/charts/line.html)、[Lightweight Charts](https://tradingview.github.io/lightweight-charts/docs)、[D3 Curves](https://d3js.org/d3-shape/curve)。
